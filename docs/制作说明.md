# 制作说明 · Steam 特惠雷达

本文档记录本作品的需求理解、架构设计、技术选型、实现细节与验证方式，便于复现与二次开发。

---

## 1. 需求理解

用户希望做一个名为「Steam 特惠雷达」的网页作品，首期核心功能是**查看最近的 Steam 每日特惠**，后续再逐步加功能。同时要求：

- 生成完整源代码；
- 部署到 **GitHub Pages**，链接必须真实可访问（只传代码不算完成）；
- 源文件与制作说明一并上传 GitHub，提交仓库链接；
- 代码类作品附运行说明。

因此本作品按「**可直接上线、可持续自动更新、便于扩展**」三个目标设计，而不是只做一个静态 Demo。

---

## 2. 整体架构

```
        Steam 商店公开接口
   (featuredcategories / search results)
                 │
                 │  Python 标准库抓取（每日 09:00 北京时间）
                 ▼
      GitHub Actions（定时 + 手动触发）
                 │
                 │  规范化 / 去重 / 生成
                 ▼
      data/specials.json   data/specials.js
                 │              │
                 │ 刷新时 fetch  │ <script> 同步加载（无 CORS）
                 └──────┬───────┘
                        ▼
        浏览器：index.html + style.css + app.js
                        │
                        ▼
              GitHub Pages 静态托管
```

架构上刻意保持**无后端、无构建、无第三方运行时依赖**：

- 数据更新放在 CI（GitHub Actions）里完成，产物就是仓库里的两个静态文件；
- GitHub Pages 只需托管仓库根目录，更新数据文件即触发重新部署；
- 前端是三个原生文件，任何人 `git clone` 后无需 `npm install` 就能跑。

---

## 3. 技术选型

| 选项 | 选择 | 理由 |
| --- | --- | --- |
| 前端框架 | 原生 HTML/CSS/JS | 作品体量小、部署目标为静态 Pages；避免构建链与依赖，长期可维护 |
| 样式 | 手写 CSS（变量 + Grid/Flex + 媒体查询） | 完全掌控视觉，实现雷达扫描、卡片悬浮等效果，零体积负担 |
| 数据抓取 | Python 3 标准库 `urllib` + 正则/`html` | GitHub Actions 上无需 `pip install`，减少失败点 |
| 定时任务 | GitHub Actions `schedule` | 免费、与仓库同生命周期、提交即触发 Pages 重部署 |
| 数据交付 | `.js` 同步加载 + `.json` 刷新 | 规避 Steam 接口的 CORS 限制，同时保留「刷新拿最新」能力 |
| 托管 | GitHub Pages（Deploy from a branch） | 与源码同仓库，最简部署路径 |

## 4. 关键实现细节

### 4.1 数据抓取脚本 `scripts/fetch_specials.py`

- **双数据源**：
  1. `featuredcategories` 的 `specials` 与 `top_sellers`：官方精选，带 `discount_expiration` 精确结束时间；
  2. `search/results?specials=1&sort_by=Discount_DESC&json=1`：按折扣降序的深度折扣榜，解析 HTML 补充更多条目。
- **字段规范化**：统一为 `id / name / discount_percent / original_price / final_price / header_image / store_url / expires_at / source / type`；把 Steam 以「分」为单位的价格换算成主货币单位（元 / 美元），并区分 `app` 与 `bundle` 生成正确的商店链接。
- **合并去重**：以 `id` 为键，精选数据优先（因为有结束时间），深度折扣补充其后，最多保留 60 条。
- **健壮性**：每个请求带 3 次重试与超时；单个区域失败时沿用上一次成功的数据；所有区域都失败时脚本以非零状态退出且不覆盖原文件，避免线上页面被清空。
- **安全输出**：生成 `.js` 时把 `</` 转义为 `<\/`，防止游戏名中若出现 `</script>` 提前闭合脚本标签。

### 4.2 为什么不用浏览器直连 Steam API

Steam 商店接口**不返回 CORS 响应头**，浏览器直接 `fetch` 会被同源策略拦截；实测公开的公共代理（allorigins / corsproxy.io）在当前网络下分别返回 Access Denied 与 401，不可作为作品的稳定依赖。

最终方案：CI 抓取 → 生成 `data/specials.js`（内容为 `window.STEAM_DEALS_DATA = {...}`）→ 页面用 `<script>` 同步加载。这样：

- 无跨域问题，也不需要后端或 Serverless 函数；
- 本地双击 `index.html`（`file://`）也能正常展示完整数据；
- 「刷新」按钮与 10 分钟自动同步改为 `fetch` 同域 `data/specials.json?t=时间戳`，拿到的是 Pages 上最新的数据快照，可靠且可控。

### 4.3 每日自动更新

`.github/workflows/update-specials.yml`：

- `cron: '0 1 * * *'`（UTC 01:00 = 北京时间 09:00），另支持 `workflow_dispatch` 手动触发；
- `permissions: contents: write`，允许把新快照提交回 `main`；
- `push` 触发条件限定在抓取脚本与 workflow 自身改动，且提交只改 `data/`，**不会造成 workflow 自触发循环**；
- 提交前用 `git diff --cached --quiet` 判断，数据无变化则跳过提交，避免无意义 commit；
- 提交后 Pages 自动重新部署，页面数据随之更新。

### 4.4 前端逻辑 `assets/js/app.js`

- 单一 `state` 对象（区域 / 关键词 / 筛选 / 排序），任何变更走同一个 `render()`，避免状态分散；
- 筛选支持全部、≥5 折、≤2.5 折、≤1 折、免费开玩；排序支持折扣、可省金额、到手价、结束时间、名称；
- 倒计时每秒刷新，24 小时内进入 `urgent` 高亮态；无结束时间的条目标注「限时特惠 · 以商店为准」；
- 图片三级兜底：原始封面 → Steam CDN `header.jpg` → 内置 SVG 占位图；
- 所有动态文本经 `escapeHtml` 转义后再插入 DOM，避免接口数据引起 XSS；
- 顶部「刷新」带 loading 态与 toast 反馈；`/` 快捷键聚焦搜索，`Esc` 清空；
- 从 `*.github.io/<repo>/` 反推 GitHub 仓库地址，页脚「项目源码」自动指向正确仓库。

### 4.5 视觉设计

深色 Steam 风（`#090f16` 底 + `#66c0f4` 蓝），折扣角标按力度从橙到深红递进，价格用绿色强调，符合「越红越划算」的直觉；Hero 区用纯 CSS 实现雷达圆环、旋转扫描扇面与闪烁光点；卡片网格 `auto-fill + minmax` 自适应，960px / 640px 两级断点适配平板与手机；支持 `prefers-reduced-motion`。

## 5. 制作过程中遇到的问题与解决

| 问题 | 处理 |
| --- | --- |
| 深度折扣列表初始解析为 0 条 | Steam 搜索页的折扣角标实际是 `<div class="discount_pct">` 而非 `<span>`，改为 `(?:span\|div)` 兼容后成功解析 45 条 |
| Steam 接口偶发读超时 | 抓取函数加入 3 次重试与 2 秒退避，实测重试后成功 |
| 浏览器无法直连 Steam API | 改为 CI 生成同域静态快照 + `<script>` 同步加载 |
| 公共 CORS 代理不可用 | 放弃第三方代理，「刷新」改为重新拉取同域 `data/specials.json` |
| 本地 `file://` 下 `fetch` 被拦截 | 主数据不走 `fetch`，用 `.js` 同步加载；刷新按钮在 `file:` 协议下给出友好提示 |

## 6. 验证方式

1. `python3 scripts/fetch_specials.py` 成功生成两个数据文件，并抽查区域数量、折扣、价格、结束时间字段；
2. 本地 `python3 -m http.server 8000` 打开页面，检查列表渲染、区域切换、搜索筛选、排序、倒计时、卡片跳转；
3. 推送 GitHub 后确认 Actions 工作流存在、Pages 已启用；
4. 用 HTTP 请求验证线上地址返回 200 且页面包含预期内容（部署结果见文末「部署与验证」）。
